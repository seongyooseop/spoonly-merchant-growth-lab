# SPOONLY 입점 매장 성장 분석: 할인·쿠폰의 실제 효과를 가르고, 예산·분담 기준·분기 예측까지

가상의 배달앱 SPOONLY(서울 동부·서울 서부·경기 남부, 2025년 52주, 매장 2,400곳, 주문 약 820만 건)를 시뮬레이션해, 배달앱 사업전략·비즈니스 분석 담당자가 하는 일을 처음부터 끝까지 보여주는 포트폴리오입니다. KPI 정의 → 매장 세분화 → 쿠폰 증분 실험 → 카테고리별 할인 반응 → 비용 분담 시범 평가 → 분기 매출 예측 → 경영진 메모 순서로 진행합니다. 데이터에 함정 다섯 가지를 넣어 두었고, 시뮬레이션이라 모든 추정치를 참값과 대조했습니다(17개 중 17개 통과).

## 데이터에 넣어 둔 함정

1. 매장은 주문이 줄어든 주에 할인을 올린다 → 매장 자체 할인으로 재면 할인 효과가 작게 보임
2. 재주문 쿠폰 사용 주문 대부분은 어차피 할 주문 → 쿠폰 사용 건수로 재면 효과가 약 3배 부풀려짐
3. 첫 주문 쿠폰으로 늘어난 신규 고객은 덜 재주문한다
4. 서울 서부 성장 등급 매장에만 30주차부터 비용 분담 시범 → 섞으면 할인 반응 추정이 오염됨
5. 연말 급증은 학습 기간에 없다 → 맞힐 수 없는 패턴을 구분해 보고

분석 코드는 원자료(data/raw)와 마트(data/marts)만 읽습니다. 참값(data/truth)은 src/validate.py에서만 씁니다.

## 가정

- 수수료 10%, 증분 주문 1건의 플랫폼 가치 4,500원(수수료 약 1,700원 + 이후 재주문 가치). 이 값이 바뀌면 쿠폰 타깃팅과 비용 분담의 기준선이 움직입니다.
- 매장 등급: 상반기(14~26주, 캠페인 주 제외) 주간 주문 중앙값 이상이면 '주문 상위', 평점 4.4 이상·배달 36분 이내면 '성장 잠재력 있음'.

## 만든 이유

Shopee에서 한국 셀러 50곳 이상을 6개 기준으로 직접 등급화해 운영했고, 행사 효과를 분리한 뒤 가격·바우처 탄력성으로 다음 행사의 할인율을 조정했으며, 회귀·MMM 기반 바텀업 시뮬레이션으로 분기 매출을 예측했습니다. 이 저장소는 같은 방법을 배달앱의 입점 매장·고객 쿠폰·비용 분담 문제에 옮겨 본 가상 케이스입니다.

## 실행

```
pip install -r requirements.txt
python src/world.py      # 가상 데이터 생성 (data/raw, data/truth)
python src/run_all.py    # SQL 마트 → 0~5장 → 참값 대조 → 보고서 페이지·요약 PDF
```

## 구조

```
src/world.py        가상 배달앱 시뮬레이션 (매장·주문·캠페인·쿠폰 실험·비용 분담 시범)
sql/marts.sql       DuckDB 마트 5개 (매장-주, 주간 KPI, 상반기 매장 프로필, 쿠폰 실험 2종)
src/analysis.py     0~5장 분석 → outputs/*.json
src/validate.py     참값 대조 → outputs/validation.json
src/build_page.py   차트·보고서 페이지(site/index.html)·1쪽 요약 PDF
```
